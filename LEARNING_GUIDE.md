# Навчальний маршрут: Reinforcement Learning на кубику Рубіка

Цей файл пояснює не лише **що запускати**, а й **що відбувається**.
Рухайся по розділах послідовно: наступний етап спирається на попередній.

## 1. Словник RL

У reinforcement learning агент взаємодіє із середовищем крок за кроком:

1. Середовище повертає **state** — поточний стан кубика.
2. Агент обирає **action** — один із 12 поворотів.
3. Середовище виконує рух і повертає **reward**.
4. Цикл триває до складання кубика або вичерпання ліміту ходів.

Основні поняття:

- **State** — 54 кольори кубика або 324-елементний one-hot вектор.
- **Action** — `U`, `U'`, `D`, `D'`, `L`, `L'`, `R`, `R'`, `F`, `F'`,
  `B`, `B'`.
- **Reward** — `+1` за складання, `-0.01` за кожен хід і додатково `-1`
  за timeout.
- **Episode** — одна спроба від перемішаного до складеного кубика.
- **Policy** — правило, за яким агент обирає наступну дію.
- **Observation** — частина state, яку ми реально передаємо агенту.

Файл `rubiks_rl/env.py` реалізує цей цикл методами `reset()` і `step()`.

## 2. Навіщо потрібен random baseline

Випадковий агент нічого не навчається. Він потрібен як нижня контрольна
точка: навчений агент має бути помітно кращим.

У `main.py` зміни:

```python
RUN_MODE = "random"
SCRAMBLE_DEPTH = 1
```

Запусти:

```powershell
python main.py
```

Результат містить:

- `success` — частку складених кубиків;
- `avg_reward` — середню суму reward за епізод;
- `avg_steps` — середню кількість зроблених ходів.

## 3. Табличний Q-learning

`TabularQAgent` зберігає Python-словник:

```text
стан кубика -> [Q для U, Q для U', ..., Q для B']
```

Q-value означає очікувану майбутню винагороду, якщо в певному стані обрати
певну дію. Після кожного переходу застосовується формула:

```text
Q(s,a) = Q(s,a) + alpha * (
    reward + gamma * max(Q(next_state)) - Q(s,a)
)
```

- `alpha` визначає швидкість навчання;
- `gamma` визначає важливість майбутніх reward;
- `epsilon` — імовірність випадкової дослідницької дії.

Для terminal state майбутнього reward немає, тому target дорівнює лише
поточному `reward`.

Запуск:

```python
RUN_MODE = "train_tabular"
TABULAR_DEPTHS = (1, 2)
```

Таблиця добре працює на коротких перемішуваннях, але кількість можливих станів
3×3 кубика занадто велика. Саме тут стає потрібна нейромережа.

## 4. Що робить DQN

Замість окремого запису для кожного state мережа в `rubiks_rl/dqn.py`
наближує Q-функцію:

```text
324 входи -> 256 нейронів -> 256 нейронів -> 12 Q-values
```

### Tensor і batch

Tensor — це багатовимірний масив чисел. Один state має форму `(324,)`.
Batch зі 128 states має форму `(128, 324)`. GPU ефективний саме тоді, коли
обробляє багато states разом.

### Forward pass

`network(states)` пропускає batch через шари й повертає таблицю форми
`(batch_size, 12)`.

### Replay buffer

Кожний досвід зберігається як:

```text
(state, action, reward, next_state, done)
```

Навчання на випадкових transition із buffer руйнує сильну часову кореляцію
між сусідніми кроками.

### Target network

Якби одна мережа одночасно створювала target і намагалася його наздогнати,
ціль постійно рухалась би. Тому є:

- `online_network` — навчається на кожному batch;
- `target_network` — заморожена копія, що оновлюється раз на 1000 кроків.

### Loss

Huber loss порівнює передбачене Q-value із Bellman target. Після
`loss.backward()` PyTorch рахує gradients, а Adam змінює weights.

Запуск:

```python
RUN_MODE = "train_dqn"
DQN_MAX_DEPTH = 5
```

Навчання починається з depth 1. Після трьох перевірок із результатом не нижче
90% depth автоматично збільшується.

## 5. Оцінювання без самообману

Під час training агент використовує epsilon exploration. Під час evaluation
`explore=False`, а seeds відрізняються від тренувальних.

Scramble actions є в `info` для тестів і показу людині, але ніколи не
передаються в `select_action()`.

Для перевірки checkpoint:

```python
RUN_MODE = "evaluate"
SCRAMBLE_DEPTH = 1
DQN_CHECKPOINT = Path("checkpoints/dqn_depth_1.pt")
```

## 6. Чому для 10 ходів потрібен пошук

Проста policy може зробити одну ранню помилку й потрапити у незнайомий state.
Тому advanced-етап розділений на дві частини:

1. `ValueNetwork` оцінює приблизну кількість ходів до цілі.
2. Weighted A* перебирає варіанти, але спочатку досліджує ті, які мережа
   вважає перспективнішими.

Value network спочатку вчиться на довжинах випадкових шляхів від цілі, а потім
уточнює оцінки Bellman-оновленнями сусідніх states.

Навчання:

```python
RUN_MODE = "train_value"
VALUE_MAX_DEPTH = 10
```

Пошук:

```python
RUN_MODE = "solve"
SCRAMBLE_DEPTH = 10
```

Пошук завжди має ліміт часу й кількості states. Знайдені actions повторно
застосовуються до кубика, тому неправильний результат не буде оголошено
розв'язком.

5. Запусти короткий DQN із `DQN_MAX_DEPTH = 1`.
6. Подивись `outputs/dqn_training.png`.
7. Лише після стабільного depth 1 підвищуй curriculum.

Не змінюй одночасно багато hyperparameters: інакше буде незрозуміло, яка саме
зміна вплинула на результат.
